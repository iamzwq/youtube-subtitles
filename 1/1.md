# YouTube 中文字幕与中文配音

自动完成：下载视频和词级字幕、选择单一字幕轨道、LLM 翻译、生成中文字幕、
Edge TTS 中文配音，以及字幕烧录和视频合成。

## 安装

**前置条件：必须先安装 FFmpeg（含 `ffprobe`）。** 脚本用它烧录字幕、探测配音
时长与合成视频，缺失时无法生成最终视频。

先进入脚本目录，并创建 Python 虚拟环境。

Windows：

```cmd
python -m venv .venv
.venv\Scripts\activate
pip install yt-dlp openai edge-tts numpy miniaudio json_repair
```

macOS：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install yt-dlp openai edge-tts numpy miniaudio json_repair
```

## 使用 uv 管理 Python（推荐）

使用 [uv](https://github.com/astral-sh/uv) 管理 Python 版本与虚拟环境，可以自动下载并固定项目所需的 Python 版本，无需手动安装和切换系统 Python。

### 1. 安装 uv

- **Windows (PowerShell)**：
  ```powershell
  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```
- **macOS / Linux**：
  ```bash
  curl -LsSf https://astral.sh/uv/install.sh | sh
  ```
- **使用 pip 安装**：
  ```bash
  pip install uv
  ```

### 2. 固定项目 Python 版本

进入脚本所在目录 `1/`，运行以下命令固定项目使用的 Python 版本（推荐使用 3.12）：

```bash
uv python pin 3.12
```

执行后会在当前目录生成 `.python-version` 文件（内容为 `3.12`）。uv 会在后续操作中自动下载并使用指定的 Python 版本。

### 3. 安装项目依赖

`uv` 支持两种依赖管理方式：

#### 方式 A：使用 `uv add`（推荐，项目管理模式）

使用 `uv add` 会将依赖写入 `pyproject.toml` 统一管理，并自动创建和更新虚拟环境：

```bash
uv add yt-dlp openai edge-tts numpy miniaudio json_repair
```

> **提示**：如果是首次在目录中运行 `uv add`，`uv` 会自动初始化 `pyproject.toml` 和虚拟环境。

#### 方式 B：使用 `uv pip install`（传统/单脚本模式）

如果不需要 `pyproject.toml` 配置文件，也可以直接用 `uv pip` 在 `.venv` 中安装依赖：

```bash
# 创建虚拟环境
uv venv

# 安装依赖
uv pip install yt-dlp openai edge-tts numpy miniaudio json_repair
```

### 4. 启动 1.py 方式

使用 `uv run` 可以直接运行脚本，`uv` 会自动加载项目固定的 Python 版本与 `.venv` 虚拟环境，**无需手动执行激活命令（activate）**：

```bash
uv run 1.py "https://www.youtube.com/watch?v=视频ID"
```

包含常用选项的启动命令示例：

```bash
# 1. 基础启动
uv run 1.py "https://www.youtube.com/watch?v=视频ID"

# 2. 指定输出根目录
uv run 1.py "https://www.youtube.com/watch?v=视频ID" -o "./my_downloads"

# 3. 仅生成字幕（不下载视频、不配音、不烧录）
uv run 1.py "https://www.youtube.com/watch?v=视频ID" --no-video

# 4. 跳过中文配音（下载视频并烧录字幕）
uv run 1.py "https://www.youtube.com/watch?v=视频ID" --no-tts

# 5. 禁用 NVIDIA GPU 硬件加速，强制使用 CPU 编码
uv run 1.py "https://www.youtube.com/watch?v=视频ID" --no-nvenc

# 6. 免下载模式（直接使用本地已有视频和字幕）
uv run 1.py "https://www.youtube.com/watch?v=视频ID" --skip-download

# 7. 清除翻译缓存并重新翻译 / 清除配音缓存并重新生成配音
uv run 1.py "https://www.youtube.com/watch?v=视频ID" --skip-download --redo-translate
uv run 1.py "https://www.youtube.com/watch?v=视频ID" --skip-download --redo-tts

# 8. 指定起始步骤（例如只重新执行步骤 8 视频合成）
uv run 1.py "https://www.youtube.com/watch?v=视频ID" --start-step 8
```

## 配置

首次运行会在脚本目录生成 `config.json`，填写 LLM API Key。默认配置包括：

```json
{
  "global": {
    "max_retries": 3,
    "sample_rate": 48000,
    "cookies_from_browser": "",
    "cookies_file": ""
  },
  "llm": {
    "base_url": "https://token-plan-cn.xiaomimimo.com/v1",
    "api_key": "你的 API Key",
    "model": "mimo-v2.5-pro",
    "supports_system_role": false,
    "thinking": { "type": "disabled" },
    "batch_size": 40,
    "batch_max_chars": 8000
  },
  "tts": {
    "enabled": true,
    "engine": "edge-tts",
    "voice": "zh-CN-YunyangNeural",
    "rate": "+0%",
    "volume": "+0%",
    "pitch": "+0Hz",
    "mix_with_original": false,
    "batch_size": 50,
    "concurrency": 5,
    "max_tempo": 1.5,
    "min_tempo": 1.0,
    "mimo": {
      "base_url": "https://api.xiaomimimo.com/v1",
      "api_key": "",
      "model": "mimo-v2.5-tts-voiceclone",
      "reference_audio": "",
      "style_instruction": "",
      "format": "wav"
    }
  },
  "subtitle": {
    "chars_per_sec": 4.2,
    "min_sentence_sec": 1.5,
    "max_merge_chars": 200
  }
}
```

`{ "type": "disabled" }` 用于关闭思考模式。但该字段是厂商自定义参数，
仅支持它的模型才会真正生效，不认识的服务可能忽略甚至报错——此时删除 `thinking`
字段即可（留空则不发送该参数）。使用其他 OpenAI 兼容服务时，修改 `base_url`、
`api_key` 和 `model`。

`supports_system_role` 仅小米 MiMo 需要设为 `false`（它不支持 system 角色，
需把系统提示并入 user 消息）；其他标准 OpenAI 兼容服务可省略该字段，走默认
`true`。

`global` 节控制全局运行参数：`max_retries` 是 LLM/TTS 调用失败时的最大重试
次数；`sample_rate` 是配音音轨拼接采样率（Hz），影响音质与解码/混音精度。

`subtitle.chars_per_sec` 是中文配音基准语速（字/秒，默认 4.2）。程序按“本句起点
→ 下一句起点”的可用时长乘以该值，算出每句译文的中文字数上限，并写入翻译
Prompt，让 LLM 主动意译精简，从源头减少配音放不进原时间槽的情况；值越大
允许译文越长、语速也会相应越快。

`cookies_from_browser` 用于让 yt-dlp 携带指定浏览器的登录 Cookie 请求
YouTube（如 `"chrome"`、`"edge"`、`"firefox"`），可显著降低下载字幕/视频时
被限流（HTTP 429 Too Many Requests）的概率。留空（默认）则不使用 Cookie。
使用该选项前需先在对应浏览器中登录 YouTube；**Chrome/Edge 等 Chromium 系
浏览器运行时会给 Cookie 数据库加独占锁**，运行脚本期间必须完全退出该浏览器
（关闭窗口不够，需确认任务管理器里没有残留的浏览器进程），否则会报错
`Could not copy ... cookie database`。Firefox 不锁库文件，一般没有此问题。

如果不方便每次运行前关闭浏览器，改用 `cookies_file` 更省心：用浏览器插件
导出 YouTube 的 Netscape 格式 cookies.txt，不依赖浏览器进程是否运行，可以
边开着浏览器边跑脚本；缺点是 cookie 会过期（一般几周到几个月），需要偶尔
重新导出。两者同时配置时 `cookies_file` 优先生效。

### 如何获取 cookies.txt

1. 在浏览器（Chrome/Edge/Firefox 均可）中安装导出 cookies.txt 的插件：
   - Chrome/Edge 应用商店搜索并安装 **"Get cookies.txt LOCALLY"**
     （开源插件，不上传数据，仅本地导出）。
   - Firefox 附加组件商店搜索并安装 **"cookies.txt"** 或同类插件。
2. 用该浏览器正常登录 YouTube / Google 账号（能正常观看视频即可）。
3. 打开 `https://www.youtube.com` 页面，点击插件图标，选择导出当前站点
   （或全部）Cookie，保存为 `cookies.txt` 文件到本地任意目录，
   例如 `D:/yt-py/cookies.txt`。
4. 将该文件路径填入 `config.json` 的 `global.cookies_file`（见下方示例）。
5. cookie 过期或重新出现 429/需要登录时，重复第 3 步重新导出并覆盖该文件
   即可，无需改动其他配置。

配置示例：

```json
{
  "global": {
    "cookies_from_browser": "",
    "cookies_file": "D:/yt-py/cookies.txt"
  }
}
```

> 注意：cookies.txt 等同于你的 YouTube 登录凭证，请勿提交到公开仓库或分享
> 给他人；建议将其加入 `.gitignore`。

## 使用 MiMo 语音克隆配音

除 `edge-tts` 外，`tts.engine` 也可设为 `mimo-voiceclone`，基于一段参考人声
样本克隆音色进行配音（适合用原视频主播本人的声音配音）。

1. 用 [extract_vocals.py](../extract_vocals/extract_vocals.py) 从原视频中提取一段干净的人声样本：
   ```cmd
   python ../extract_vocals/extract_vocals.py "D:\video.mp4" -f wav
   ```
2. 在 `config.json` 中把 `tts.engine` 改为 `"mimo-voiceclone"`，并在 `tts.mimo`
   中填写：
   - `reference_audio`：上一步生成的 `*_vocals.wav`（或 `.mp3`）路径；
   - `api_key`：MiMo TTS 的 API Key（留空则复用 `llm.api_key`）；
   - `style_instruction`：可选，自然语言风格指令（如“语速稍快，语气自然”）。

限制：

- 参考音频仅支持 `mp3` / `wav`，Base64 编码后不能超过 10 MB（原始文件建议
  控制在 7 MB 以内，且不宜过长，几秒到几十秒的清晰人声样本即可）；
- 该模型不支持唱歌模式、预置音色与音色设计；
- `rate` / `volume` / `pitch` 仅对 `edge-tts` 生效，`mimo-voiceclone` 请改用
  `style_instruction` 控制语气与语速。

## 字幕与翻译

- 优先选择视频语言对应的自动字幕，只下载一条字幕轨道。
- 自动字幕不可用时，再回退到人工字幕，不会同时下载两类字幕。
- 为防止 YouTube 频繁请求导致的 HTTP 429 限流，下载命令默认开启 `--sleep-subtitles 2` 延迟间隔，并在遇到 429 时自动进行指数退避重试（5s / 10s / 20s）。
- `[Music]`、`[Applause]`、`(upbeat music)` 和音符符号会被移除；只含这些内容的
  字幕会被丢弃。
- 原句时长低于 `min_sentence_sec`（默认 1.5 秒）时会与相邻句合并为一个
  翻译/配音单元，避免过短时间槽导致配音要么被迫拉长要么严重加速；单次合并
  的原文字符数不超过 `max_merge_chars`（默认 200），防止连续短句无限合并。
- LLM 每批最多翻译 40 句、8,000 个原文字符，并按批保存翻译缓存。
- 翻译不再注入视频简介（噪音多且与具体句子无关），改用**前后文滑动窗口**：每批
  附带前 3 句已完成的中文译文与后 3 句原文预览，提升代词指代与语境连贯性。
- 每句带有按可用时长换算的**中文字数上限**（见 `subtitle.chars_per_sec`），写入 Prompt
  让 LLM 主动精简译文，从源头避免配音超时、减少大幅变速。
- `zz`、`qq`、`Ctrl+Z`、`F5`、`:wq`、`save_file` 等快捷键、命令和代码
  字面量除 Prompt 指令外，还会在**术语表提取**阶段被录为 `zz → zz` 这类
  自映射词条，以术语表的强约束防止模型把重复字母当成拼写错误“纠正”。
- 翻译缓存会在字幕内容（哈希）或模型名变化时整体失效；重新运行会从未完成位置
  （按句编号）继续翻译，已完成的句子不会重新请求。
- 当前英文分句主要依赖原字幕标点；没有标点的自动字幕可能形成较长句子。

## TTS 缓存

- TTS 每批最多生成 50 条，最多同时请求 5 条。
- `tts_cache.json` 会校验字幕文本和 TTS 配置，避免复用错误音频。
- 中途失败时保留已经生成的音频，重新运行时跳过有效缓存。
- 最终视频成功生成后，才删除 TTS 音频、混合音频和 TTS 缓存清单。
- FFmpeg 或 TTS 失败时，缓存会保留；成功后缓存会被清理，这是正常行为。

## 输出目录

产物位于 `输出目录/视频ID/`：

```text
视频ID.mp4                 原始视频
视频ID.jpg                 视频封面
视频ID.<语言>.json3        原语言词级字幕
```

最终视频包含中文字幕和中文配音；如果标题翻译失败，则使用原标题命名。

## 配音与字幕时间轴对齐

全程保持 **1 句原文 = 1 条译文 = 1 段配音 = 1 条字幕**，时间轴采用**硬锚定**：

- 每句起始时间严格等于原句起始时间，绝不因上一句配音超长而顺延，从根本上
  杜绝音画滞后随视频推进而累积。
- 单句可用时长 = 本句起点 → 下一句起点（含句间静音间隙）。
- 配音明显短于可用时长时，会在 `min_tempo`（默认 1.0，即不放慢）到 1.0 倍之间
  轻微放慢填充；需要放慢填白时可把该值调低（如 0.9）。
- 配音超出可用时长时，仅在 `max_tempo`（默认 1.5）以内加速；仍放不下则在下一句
  起点处淡出截断（翻译阶段的字数预算已从源头抑制这种情况；如仍频繁出现，
  可调低 `subtitle.chars_per_sec` 让译文更精简）。
- 变速优先使用 ffmpeg 的 `rubberband` 相位声码器滤镜（音质明显优于
  `atempo`），仅当 ffmpeg 未编译该滤镜时才自动回退到 `atempo`。

## GPU 加速（NVENC）

烧录字幕需要重新编码视频，是最耗时的步骤。若检测到支持 NVIDIA NVENC 的
ffmpeg 和显卡，会自动使用 GPU 硬件编码（`h264_nvenc`）替代 CPU 编码
（`libx264`），显著缩短烧录时间。

- 检测分两步：先查编码器列表，再空转编码 1 帧确认驱动/显卡真正可用。
- 检测失败或用 `--no-nvenc` 时，自动回退到 CPU `libx264`。
- 仅烧录字幕时涉及编码器选择；纯替换配音走 `copy`，不重新编码。
- 需要带 NVENC 的 ffmpeg 构建，可用 `ffmpeg -encoders | findstr nvenc`
  确认是否包含 `h264_nvenc`。
